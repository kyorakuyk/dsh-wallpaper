# dsh-wallpaper v0.3 产品级重构计划

## 1. 目标与重构原则

本次开发按产品级重构实施，不继续围绕现有窗口代码做最小修改。保留能够验证价值的协议、领域类型和素材，重新建设 Windows 桌面承载、运行时状态、交互 UI、主题系统和视觉资产管线。

最终产品应满足：

- Windows 11 单主屏下成为真正的交互式桌面壁纸。
- 执行 `Win+D` 或“显示桌面”后仍显示 dsh-wallpaper，不露出系统设置的静态壁纸。
- 桌面图标、右键菜单、拖拽、任务栏和普通程序不受影响。
- 睡眠、解锁苏醒、待机人物、聊天和后端切换构成连贯体验。
- 中央聊天 UI 是融入背景的半透明悬浮组件，不表现为普通应用窗口。
- 普通程序位于前台时交互 UI 自动隐藏；回到桌面时按用户状态恢复。
- 用户可以不编辑代码或 JSON，完成主题、背景、立绘等外观定制。

明确不做：

- 不接管 Windows 密码页或实现 Credential Provider。
- 首版不支持多显示器和 Windows 10。
- 不允许用户主题直接执行 JavaScript 或系统命令。
- DeepSeek Web 适配器未完成前，不把它宣传为可正常工作的默认聊天能力。

## 2. Windows 桌面架构

### 2.1 窗口分层

应用使用两个职责严格分离的表面：

```text
Windows WorkerW
└─ Background WebView
   ├─ 睡眠/苏醒场景
   ├─ 桌面背景
   └─ 人物与纯视觉效果

Desktop Interaction Overlay
├─ 人物交互热区
├─ 中央聊天气泡
├─ Popover / Drawer / Toast
└─ 设置与素材管理
```

- `background` 必须成为 WorkerW 壁纸宿主的一部分，只负责渲染，不获取输入焦点。
- `interaction` 是透明无边框 Overlay，只在桌面处于前台时可见。
- Overlay 的非交互区域通过 `WM_NCHITTEST -> HTTRANSPARENT` 把输入传给桌面。
- 收起态使用 `WS_EX_NOACTIVATE`；用户点击输入框时才允许获得焦点。
- Overlay 不使用全局 `alwaysOnTop` 压住普通应用。
- 背景窗口不得监听全局 `pointerup`，交互仅由明确的热区触发。

### 2.2 WorkerW 技术验证

正式重构前完成两个原生样例：

1. 先创建原生 WorkerW 子窗口，再把 WebView2 挂入宿主。
2. 若普通 WebView2 在 WorkerW 下出现灰屏或 DirectComposition 异常，改用 WebView2 Composition Controller/DirectComposition。

只有通过以下门槛的方案才能进入主线：

- 连续执行 50 次 `Win+D` 不露出系统壁纸。
- Explorer 重启后能够自动寻找新 WorkerW 并重新附着。
- 分辨率、DPI、任务栏状态变化后尺寸正确。
- 不依赖延迟循环反复执行 `SetWindowPos`、`show()` 或 ±1px 重绘。
- 桌面图标、选择框、右键菜单和拖拽正常。

### 2.3 系统事件

Rust 层统一监听：

- WTS 锁定与解锁。
- 睡眠与恢复。
- Explorer/Shell 重建。
- 前台窗口变化。
- 显示器、DPI 和工作区变化。

解锁后 500ms 内开始苏醒动画；锁定时隐藏所有聊天内容，但正在进行的模型请求不强制取消。

### 2.4 锁屏接管正式交付（待做）

当前开发版已验证本地 PNG 准备、原锁屏静态图片备份与恢复流程；但部分 Windows 11 环境会拒绝无包身份的 `tauri dev` / NSIS 桌面程序写入锁屏。此项不阻塞桌面壁纸和聊天主线，暂列为待办，完成标准如下：

- 增加可本地安装的 MSIX 测试包、开发证书与签名脚本。
- 在已安装 MSIX 中验收锁屏图片设置、恢复、Spotlight 限制提示与 Win+L 流程。
- 保留 NSIS 作为常规安装包；其锁屏设置须清晰提示“需要 MSIX 包身份”，不得显示为已生效。
- 正式发行前决定采用 Microsoft Store 签名 MSIX、企业签名 MSIX，或将锁屏接管保持为 MSIX-only 可选能力。

## 3. 运行时与代码结构

### 3.1 Rust 是唯一状态源

建立 `AppCore`，统一维护：

- `SystemPhase`
- 当前后端、模型、模型层级与思考强度
- Harness 可用性和探测状态
- 当前会话、消息流和使用量
- 当前主题、局部覆盖和交互层显隐
- 系统锁定、解锁与前台应用状态

两个 WebView 只订阅状态快照和类型化增量事件，不再各自创建聊天适配器、3080 探测器或独立业务状态。

建议目录：

```text
wallpaper/src/
  app/
  domain/
  runtime/
  backends/
  features/
    chat/
    persona/
    wake/
    settings/
    theme-manager/
    session/
  scenes/
  ui/
    primitives/
    tokens/

wallpaper/src-tauri/src/
  app_core/
  windows/
  services/
  commands/
```

### 3.2 统一事件

所有后端继续转换为统一 `ChatEvent`，UI 不理解 DeepSeek DOM、API SSE 或 DSH SessionEvent。

新增运行时快照事件：

```ts
interface AppSnapshot {
  phase: SystemPhase
  backend: BackendMode
  model?: ModelDescriptor
  harness: HarnessStatus
  chat: ChatSnapshot
  appearance: AppearanceState
  interaction: InteractionState
}
```

- Rust 在状态变更后发布带版本号的完整快照。
- 聊天文本流可使用增量事件，但最终消息必须写回 `AppCore`。
- WebView 重建或丢失事件时，重新请求完整快照即可恢复。

### 3.3 后端修复

- Harness 探测只能有一个实例，禁止重叠请求。
- DSH bridge 保留现有版本化 REST/SSE 协议，并补充真实集成测试。
- API 会话由 Rust 保存多轮上下文，`conversationId` 不得再被忽略。
- API 使用量和价格配置在 Rust 中计算，提供本轮与会话累计费用。
- API Key 仅存 Windows Credential Manager。
- DeepSeek Web 未实现可靠 DOM adapter 前显示为“实验能力，暂不可用”，不自动切换付费 API。
- 用户设置和会话指针迁移到原生版本化存储，不使用 `localStorage` 保存正式数据。

## 4. UI 与视觉设计

### 4.1 设计系统

把当前单体 CSS 拆为设计令牌、基础组件、功能组件和场景样式。

统一令牌包括：

- 背景与文字色阶。
- 玻璃透明度、模糊和饱和度。
- 外阴影、内高光和边缘描线。
- 圆角、间距、字体和动画曲线。
- DeepSeek 蓝色与 Harness 黑红色主题变量。

两种后端使用相同组件和布局，只替换色彩、纹理和氛围效果。支持 Windows“减少动画”和高对比度降级。

### 4.2 官方交互布局

交互层使用独立局部窗口，不再创建覆盖整个桌面的透明 WebView。窗口的真实 HWND 区域只包含当前可见组件，区域外由 Explorer 原生处理桌面图标、框选、拖拽和右键菜单。

官方提供两种可切换布局：

#### 中央悬浮模式（默认）

- 收起态为屏幕视觉中心附近的半透明玻璃胶囊，展示问候、后端、模型和活动状态。
- hover 时仅轻微上浮并增强阴影，不做夸张缩放。
- 输入态展开为约 640px 宽的半透明玻璃卡片。
- 支持拖动和吸附；位置以工作区内的归一化坐标保存，不保存绝对物理像素。
- 分辨率、DPI 或屏幕方向变化后，原生层将位置重新约束到安全工作区。

#### 任务栏停靠模式

- 收起态只显示紧靠任务栏内侧的展开按钮，不覆盖任务栏和自动隐藏触发带。
- 任务栏在底部时向上展开；顶部向下；左侧向右；右侧向左。
- 无法识别任务栏位置时，以工作区底边作为安全降级。
- 展开尺寸受当前工作区约束，最大不超过工作区的 90%。
- 点击收起按钮、按 `Esc` 或托盘“隐藏对话”后恢复为停靠按钮。

两种布局共享以下行为：

- 使用背景模糊、细边缘高光、内阴影、柔和投影和低对比噪点纹理。
- 历史记录从输入框上方展开，顶部和底部使用渐隐处理。
- 生成中使用低频流光或状态呼吸，不使用持续高负载粒子。
- 错误显示为 Toast 或气泡内状态行。
- DSH 上线提示内联显示在气泡中。
- 设置使用右侧 Inspector Drawer。
- 后端、主题和素材快速切换使用锚定 Popover。
- 除文件选择器和 DeepSeek 官方登录外，不创建独立弹出窗口。

### 4.3 工作区驱动的几何系统

所有窗口定位以 Windows 返回的实际工作区为准，禁止写死 16:9、1920×1080、底部任务栏或固定任务栏高度。

```ts
interface DesktopGeometry {
  monitorId: string
  monitorBounds: Rect
  workArea: Rect
  scaleFactor: number
  taskbar: {
    edge: 'top' | 'bottom' | 'left' | 'right' | 'hidden' | 'unknown'
    bounds?: Rect
    autoHide: boolean
    visible: boolean
  }
  revision: number
}
```

原生层使用 `MonitorFromWindow`、`GetMonitorInfoW`、`SHAppBarMessage` 和系统工作区信息采集几何状态，并监听 DPI、显示器、工作区、任务栏和 Explorer 变化。连续事件合并 50–100ms 后发布一次递增 revision。

布局约束：

- 以 DIP 完成组件计算，再转换为当前显示器的物理像素。
- 悬浮宽度采用 `clamp(360 DIP, workArea × 34%, 680 DIP)`。
- 展开高度采用 `clamp(320 DIP, workArea × 52%, 760 DIP)`。
- 工作区宽度低于 720 DIP 时切换紧凑单列；竖屏不使用横向人物/对话并排布局。
- 每个关键操作按钮至少 32×32 DIP，推荐 40×40 DIP。
- 始终保留至少 12 DIP 安全边距和可见的收起按钮。
- 自动隐藏任务栏保留 2–4 个物理像素的系统边缘触发带。
- 用户保存的位置落到屏幕外时自动恢复到视觉中心。
- 主题包只能提供推荐尺寸和视觉参数，不能突破原生安全边界。

首版仍以单主屏为验收目标，但接口按 `monitorId` 设计，避免阻断后续多显示器支持。

### 4.4 任务栏视觉融合

任务栏透明化作为可选增强功能，不默认开启：

```text
跟随系统
半透明亚克力（推荐）
完全透明（实验）
```

- 仅在桌面处于前台时应用，普通窗口最大化、开始菜单打开或应用退出时恢复系统样式。
- Explorer 重启后重新探测并按用户设置应用。
- 不注入 `explorer.exe`，不修改系统文件。
- 检测到 TranslucentTB 等同类工具时停止争抢并提示用户选择唯一管理者。
- 非公开 Windows 组合属性必须标记为实验能力，失效时自动退回“跟随系统”。

当前实现状态（2026-08-17）：旧 `SetWindowCompositionAttribute/ACCENT_POLICY` 技术样例在当前 Windows 11 XAML 任务栏上返回成功但没有视觉效果，因此不能作为正式实现。设置页暂时锁定“跟随系统”；后续需完成 Win11 专用技术样例、外部美化工具冲突检测和“仅桌面前台启用”后再开放亚克力与完全透明模式。

冻结集成决策：主程序不复制 TranslucentTB 源码、不注入 Explorer、不修改其配置。设置页只检测独立安装与运行状态，允许用户启动 `ttb.exe`，或打开其官方 Microsoft Store 产品页（`9PF4KZ2VN4W9`）。透明风格和自动化规则继续由 TranslucentTB 自身管理。该松耦合集成不把 TranslucentTB 二进制或 GPL 源码纳入 dsh-wallpaper 安装包。

### 4.4.1 已知交互窗口缺陷

- 中央浮动会话窗已使用非空区域显示闸门与 DWM cloak，关闭时的空白窗口闪烁已消除。
- 个别设备在首次或偶发打开时仍可能出现一帧空白 WebView/DWM 合成画面。
- 该问题暂不阻塞任务栏与主题系统开发；后续应基于 WebView2 首帧/合成完成信号替代当前 DWM flush 揭幕策略，并补充高速录像验收。

### 4.5 立绘融合

现有白底 JPEG 不再通过整体蓝色遮罩或简单 CSS filter 处理。四张正式立绘需要生成：

```text
portrait-base.webp
ambient-mask.webp
warm-key-mask.webp
rim-light-mask.webp
contact-shadow.webp
portrait-preview.webp
```

处理要求：

- 语义抠图并人工检查头发丝、裙边、鲸尾和手部。
- 清除白色背景产生的白边和颜色污染。
- 加入水下蓝色环境光、左侧台灯暖光和窗户青色轮廓光。
- 使用局部遮罩保护皮肤、白围裙和高光，不把整个人统一染蓝。
- 增加符合摆放位置的接触阴影与环境遮蔽。
- 四种形态的视觉重心、头部位置和交互热区保持一致。
- 在 100%、125%、150% DPI 下输出实际背景合成截图验收。

### R1.5：几何与布局引擎

- 实现 `DesktopGeometry` 原生采集、revision 和类型化事件。

### R1.6：表 / 里双层桌面工作台

产品将壁纸空间定义为两个应用内工作区，而不是 Windows 虚拟桌面：

- `front`（表桌面）：Windows 原生桌面。Explorer 图标、文件、快捷方式、框选、拖拽与右键菜单完整保留。
- `inner`（里桌面）：壁纸工作台。承载中央会话窗以及未来的时钟、日历、提醒事项和第三方组件。
- 双击表桌面空白区域进入里桌面；双击里桌面空白区域或按 `Esc` 返回表桌面。
- 图标、文件、任务栏、会话窗和组件内部的双击不得触发工作区切换。
- 该切换只改变壁纸应用自身的视觉与交互状态，不创建或切换 Windows 虚拟桌面，不影响已打开应用。

工作区状态：

```ts
type DesktopWorkspace = 'front' | 'entering-inner' | 'inner' | 'leaving-inner'
```

进入动画固定为：背景景深轻微增加 → 中央出现模糊边框 → 边框展开并清晰 → 会话输入舱获得焦点 → 其他组件依次出现。退出时反向播放，总时长控制在 220–320ms，并遵循系统“减少动态效果”设置。

布局语义同步调整：

- `floating`：进入里桌面后中央会话输入舱默认保持展开，不使用中央胶囊作为常态入口。
- `taskbar-docked`：表桌面保持任务栏内侧的小型展开按钮，点击后向工作区内部展开。
- 会话历史继续从中央输入舱上方展开，不把主输入舱改造成传统竖向聊天窗口。

桌面空白双击检测必须为非侵入式原生能力：监听但不吞掉 Explorer 鼠标输入，通过桌面 ListView 命中测试确认点击处无图标，并排除拖动、框选和右键流程。禁止注入 Explorer，禁止使用全屏透明窗口覆盖桌面。

里桌面组件采用受控插件容器。第一阶段只冻结 manifest、布局、主题、存储与事件接口，不立即内置时钟、日历或提醒事项。第三方组件默认不得直接访问文件系统、网络、密钥、Cookie 或 DSH bearer token。

- 任务栏上、下、左、右，不同厚度以及自动隐藏开启/关闭。
- 运行时移动任务栏、修改缩放、切换分辨率和旋转屏幕。
- 3080 未启动、端口被占用、无 bridge、bridge 中途退出。
- 锁屏发生在流式回复或工具运行期间。
- 安装、卸载、锁屏恢复、资源缺失和损坏配置恢复。

首版发布必须满足：

- 连续 50 次 `Win+D` 不露出系统壁纸。
- 解锁后 500ms 内开始苏醒动画。
- 冷启动进入桌面后 3 秒内出现背景。
- 背景层不捕获全屏输入。
- 交互窗口不覆盖任务栏，且任何几何变化后收起按钮都保持可见。
- 待机 CPU/GPU/内存适合长期运行。
- 正式包不包含候选图、生成脚本和中间文件。
- 前端构建、类型检查、单元测试、Rust 测试和 Win11 冒烟测试全部通过。

## 6. 可并行交付边界

可以独立交给其他开发者的任务：

- UI primitives 与设计令牌：只依赖明确的组件 props，不接触窗口原生代码。
- 立绘资产处理：按固定输出文件和遮罩规范交付。
- 主题 manifest/schema 校验器：按主题系统文档实施。
- API 多轮与计费服务：只在 Rust service 层实现并输出 `ChatEvent`。
- DSH bridge 集成测试：不修改 Windows 窗口架构。

不得在 WorkerW 原型选型完成前并行修改正式窗口定位代码，也不得通过新增延时线程或 Z 序循环暂时绕过问题。
