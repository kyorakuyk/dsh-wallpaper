# dsh-wallpaper 多屏支持

## 当前范围

多屏设置属于完整版的实验能力；Lite 首发仍保持单主屏范围。完整版会在检测到两个或更多显示器后，在“设置 → 常规”显示“多屏桌面”卡片。

当前实现支持：

- 枚举 Windows 显示器设备名、物理边界、工作区、主屏标记和有效缩放比例；
- 每块屏幕从官方背景目录中独立选择背景，未单独选择时跟随全局背景；
- 会话窗和立绘分别选择所在屏幕；
- 保留一个 WorkerW/WebView 宿主，但把每块屏幕绘制成独立的 CSS 图层；
- 多屏交互层按 WorkerW 的 CSS device-pixel ratio 缩放，输入岛的物理尺寸不会因主屏高 DPI 被放大；缩放锚点随停靠/悬浮/历史展开状态保持不变；
- 未改变背景选择的屏幕由 `React.memo` 和 `contain: paint` 隔离，避免无意义的 React 更新和尽量减少浏览器重绘。

## 坐标与缩放

Rust 以 Windows 虚拟桌面的物理像素坐标返回矩形。前端先计算所有显示器的虚拟边界，再将每块屏幕转换为宿主视口中的百分比矩形，因此左侧或上方带负坐标的显示器也能正确定位。立绘的环境采样使用目标屏幕自己的宽高，不再采样整张虚拟桌面。

显示器拓扑变化、DPI 变化和宿主窗口尺寸变化会触发重新查询；设置页同时提供手动刷新入口。保存的设备名失效时，应用回退到主屏，再回退到当前枚举结果的第一块屏幕。

## 渲染边界

多屏独立背景只在待机/工作场景启用。睡眠和苏醒帧仍使用同步叙事画面，保证解锁动画在所有屏幕同时推进；后续如果需要每屏不同动画，应另行设计素材和缓存策略。

当前不承诺：

- 每屏独立的用户主题包素材覆盖；
- 多个独立 WebView 宿主；
- 多屏锁屏图片分别接管；
- 未经真机验证的混合 DPI 像素级无缝边界。

## 验收重点

在 Windows 11 上至少验证：左右/上下排列、不同分辨率、125%/150% 混合缩放、主屏切换、显示器拔插、任务栏位于不同屏幕，以及会话窗/立绘移动后其他屏幕背景不闪烁。若出现定位偏差，先记录 Rust 返回的设备名、边界和缩放，不要直接修改注册表或切换 Shell。
