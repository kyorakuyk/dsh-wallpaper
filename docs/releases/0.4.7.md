# DSH Wallpaper 0.4.7（完整版 · Windows 11）

两件事：**升级真正一键**（不再有维护页与向导页），以及**修一个把文件藏深了一层的路径 bug**。

## 一键升级

现在点「点击安装」之后：**应用自己关掉 → 只显示一个进度条 → 装完自动起新版**。没有维护页（不再问"先卸载还是不卸载"）、没有目录选择、没有开始菜单页。

做法：以 **passive 模式**（`/P`）启动安装器。模板里带 `SkipIfPassive` 的页面（欢迎、目录、开始菜单、完成）全部跳过；而"已安装"维护页在 passive 下**根本不建对话框**，只跑它自己的离开逻辑。

**一个要说明的取舍**：passive 分支选择的是**原地覆盖安装**，而不是"先卸载再安装"（这是 Tauri 模板在该分支的既有行为）。好处是**不会删掉开机自启项与快捷方式**，也不会出现"旧版卸了、新版没装上"的空档；代价是旧版多出来的文件会留在安装目录里。

（应用先自己退出这条仍然保留——那是为了让安装器能替换被占用的 exe。）

## 修好的路径 bug（顺带回收 178 MB）

状态文件与**每个已下载的安装包**原本落在：

```
%LOCALAPPDATA%\com.dsh.wallpaper\com.dsh.wallpaper\updates\
                                ^^^^^^^^^^^^^^^^^ 多了一层
```

原因：Tauri 的 `app_local_data_dir()` **本身已经带上 bundle 标识符**，代码又拼了一次。

**为什么一直没被发现**：读写都在同一个错路径上，功能自洽——检查、节流、忽略、下载、安装全都正常。只有去寻找那个文件的人才会发现目录是空的。

**现在**：首次用到时自动迁移（同卷改名，常数时间；搬不动就删；失败只记日志，绝不拖启动链）。本机实测：**回收 178.2 MB**（0.4.3 / 0.4.4 / 0.4.5 三个旧安装包），嵌套目录消失，状态文件里的下载路径已改写指向新位置、摘要原样保留。

顺带：**每次更新成功后清理非当前版本的安装包**（此前每升一版白留约 59 MB）。

## 怎么验

从 **0.4.6 升到 0.4.7**：点「点击安装」→ 应用关闭 → **只看到进度条** → 装完新版本自己起来。升级后确认设置、会话记录、素材库都在，且 `%LOCALAPPDATA%\com.dsh.wallpaper\updates\` 里只剩当前版本那一份安装包。
