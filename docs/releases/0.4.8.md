# DSH Wallpaper 0.4.8（完整版 · Windows 11）

这一版修的是**偶发自动退出**——真机实测到的问题——并让**下一次崩溃自己留下证据**。

## 问题与根因（有崩溃转储与指令级证据）

应用会偶发崩溃（9 月 27 日起至少四次，崩溃点在应用自身）。把 `%LOCALAPPDATA%\CrashDumps\` 里的转储符号化后，得到的是**一族**问题，不是几个独立 bug（0.2.0 与 0.4.7 两次崩溃的故障指令与寄存器布局**逐条同构**）：

> 后台线程调用 `AppHandle::get_webview_window(...)`。这个调用会 clone `Webview`，进而动 wry 共享上下文的引用计数——**这类运行期状态只能在事件循环线程上碰**。内存被写坏之后，崩溃会**很久以后**才在主线程的消息派发里出现，所以表现为"有时莫名其妙自己退出"。

**修了四处**（同一族）：

| 处 | 频率 |
| --- | --- |
| 桌面工作区监视线程 | 16 毫秒一次 |
| 前台监视线程 | 120 毫秒一次 |
| 悬浮球监视线程 | 16 毫秒一次 |
| 悬浮球"准备弹出"的判据 | 同上 |

做法：**窗口句柄在主线程解析一次**，线程里只用整数句柄与 Win32 `IsWindow`；需要读缩放与尺寸时改问 `GetDpiForWindow` / `GetClientRect`（它们正是原来那两处值的来源）。

**顺带修掉一个我自己引入的缺陷**：句柄如果只解析一次并冻结，当 `background` 窗口被**销毁并重建**（宿主自愈路径，它存在的意义就是应付这个）时，旧句柄永远失效 ⇒ 桌面工作区监视线程退场 ⇒ **双击桌面进里桌面从此永久失效**；悬浮球则表现为**再也不弹出**。现在句柄放在**共享槽位**里，由主线程在窗口创建与重建处写入，监视线程每拍原子读一次；**读到已销毁句柄时继续等而不是退场**（因为那是重建的中间态，退场正是要修的失效本身）。

## 新的：崩溃时自己写证据

- **报告** `%LOCALAPPDATA%\com.dsh.wallpaper\logs\crash-<时间戳>.txt`：异常码与参数、故障地址换算成**模块+偏移**、出错线程的调用栈、**自动附带应用日志尾部**（日志会被轮换，之前"0 字节"就是这么来的）、已加载模块表；
- **全量内存转储** `%LOCALAPPDATA%\com.dsh.wallpaper\crashes\crash-<时间戳>-<异常码>.dmp`：带出错线程上下文，调试器打开就能停在故障指令上；只保留最近 3 份，**只删匹配这个命名的文件**，写失败会删掉半截文件并如实记原因；`DSH_WALLPAPER_NO_CRASH_DUMP=1` 可关、`DSH_WALLPAPER_CRASH_DUMP_DIR` 可换目录；
- **绝不吞异常**：两个原生处理器把异常原样交回系统（有测试钉住返回值），系统错误提示与 WER 不受影响。

施工里还发现并修掉两处**只有驱动真实处理器才会暴露**的自身缺陷：转储入口重复抢同一把重入旗（会让生产环境里原生崩溃与 panic **一个字节都写不出来**），以及一个 UTF-8 字面量写错（小于 1 MB 的转储大小报空）。

## 每次发布保留符号

构建时把 `dsh_wallpaper_<版本>.pdb` 留在 `dist\<版本>\` 并打印哈希；找不到符号只告警、不拦发布。原因很直接：**这台机器上更早的四次崩溃已经永远读不出来了**，因为当时的符号不在。读转储的手册见 `docs/diagnostics/crash-dumps.md`（用 WinDbg 包内自带的 `cdb.exe`，**不需要装 Windows SDK**）。

## 这一版**没有**修的（写在这里，不等你自己撞上）

**`deepseek_web.rs` 一族还有 6 处同类**：`send` / `cancel` / `status` / `history` 在 async 命令体里（跑在 tokio 线程），`ensure` / `show_login` 在阻塞池线程，另有一处 `window.clone()` 被丢进线程并在后台 Drop。它们与已确证的崩溃**同族**，但要改的是设计（async 边界、时序），属于单独一轮的工作。

另外：既有防线只抓"后台线程带着主线程标记"，**抓不到"后台线程直接碰运行期窗口状态"**——这句话现在写在代码里了（悬浮球那次就是漏在这个盲区）。所以纪律不是"有防线就安全"，而是**取窗口对象只能在主线程做**。

## 怎么验

**观察 1 到 2 周**（基线是相隔一个月的两次崩溃，当天不崩不算证据），看：

1. 日志里不再出现新增的"线程亲和性违例"行；
2. `%LOCALAPPDATA%\CrashDumps\` 与 `%LOCALAPPDATA%\com.dsh.wallpaper\crashes\` 不再新增转储。

**窗口重建**这条路值得单独手工验一次：在任务管理器里重启 `explorer.exe`，等 2 到 5 秒（自愈周期 2 秒），确认日志里出现宿主自愈相关记录，然后**不重启应用**逐项试：双击桌面空白处进/出里桌面、光标移到底部中央能否弹出球、回到桌面后键盘输入是否正常。若这几项在重建后仍可用，句柄槽位这条修复就算验到了。

**万一还崩**：把 `logs\crash-*.txt` 与 `crashes\crash-*.dmp` 留着——这一次手里会有应用自己写的栈、全量内存，以及**与构建对应的符号**。
