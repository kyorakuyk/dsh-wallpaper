# DSH Wallpaper 0.3.2（完整版 · Windows 11）

修的是 0.3.0 / 0.3.1 上线后暴露出来的几处：**设置里的提示会误导人**、**没装 TUI 也摆出那个选项**，
以及**每次启动都在动你的档案**。

## 这一版改了什么

**桥**

- **不再为别人的插件报警**。DSH 装包时会检查档案里**所有**插件，并可能为**别的**插件打印"版本豁免"
  提示；0.3.1 会把这种提示当成本次安装需要你确认，于是弹出"桥已装好，但需要你确认版本豁免"——
  而实际上你什么都不用做（隔壁机器上就被这句话吓到过）。现在只有提示**点名桥自己**时才交给你决定。
- **版本相符时什么都不做**。此前即使版本已对，每次启动仍会跑一遍包管理，pnpm 会把 `pnpm-lock.yaml`
  重写一遍——等于每次启动都在你的档案上留一个指纹。现在先读档案里的版本，相符就直接收场。
- **设置窗口真的能调用这条命令了**。0.3.0/0.3.1 上打开设置会看到
  `装桥失败：Command ensure_profile_bridge not allowed by ACL` —— 那不是文件权限问题，而是新命令没登记进
  应用的能力清单，**任何机器上都会失败**。桥本身不受影响（启动时的对齐在原生侧），但设置里那条反馈链
  是断的，现在通了。
- 出错时的**原始输出完整写进日志**（界面仍然只显示摘要），判读规则万一再错，有原文可算。

**界面**

- **没装 TUI 就不再显示「终端里的 TUI」**：扫描主体时顺带查一次（`dst`，走 npm 全局前缀与 `PATH`），
  没有就只剩「浏览器」。以前那个选项点下去只会报"本机没有找到 TUI"——那不是选项，是坑。
- 已经存过"用 TUI 打开"的人不会卡住：只剩一条路时自动回落到浏览器。

**打包**

- MSIX 测试包不再自称锁屏包（显示名、描述与产物文件名都改了）；
- 能力清单里指向已退出功能的授权条目已清掉。

## 安装

到 [Releases](https://github.com/kyorakuyk/dsh-wallpaper/releases) 下载
`dsh-wallpaper_0.3.2_x64-setup.exe` 双击即可 —— **当前用户、不请求管理员、不需要证书**，
卸载走「应用和功能」。安装器未签名，第一次运行会有一次 SmartScreen 提示（更多信息 → 仍要运行）。

从 0.3.0 / 0.3.1 升级：直接装，覆盖即可；设置、素材与桥令牌都在原处不动。

**harness 模式**需要机器上有 DSH（官方客户端，或 `npm i -g @deepseek-ai/dsh`）；桥由壁纸自己对齐，
装不上时设置里会说清原因。遇到需要"精确版本豁免"的提示时**要你自己确认**——壁纸只转达，不代你点。
