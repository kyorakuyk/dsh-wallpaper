# DSH Wallpaper 0.4.6（完整版 · Windows 11）

更新安装**回到一步**：不再先弹一个卸载器、再进安装向导。

## 问题与真正的根因（并更正前两版的说明）

从 0.4.3 及更早的版本点更新时，用户看到的是**两步**：先一个带界面的卸载器，然后才是安装向导。

**前两版发布说明把原因归给"应用仍在运行、安装器替换不了 exe"——那是错的。** 这一版施工时读安装脚本、并做了对照实测，真正的根因是：

> **Tauri 的 NSIS 模板调用旧版卸载器时从来不传 `/S`。**

测法：给一个探针卸载器分别传两种参数，看卸载器内部读到的 `${Silent}`：

| 传给旧卸载器的参数 | `${Silent}` | 结果 |
| --- | --- | --- |
| `_?=<目录>`（上游现状） | **0** | **带界面** ⇒ 两步 |
| `/S _?=<目录>` | 1 | 静默 |

（0.4.4 那次"应用先自己退出"**仍然必要**，但它解决的是另一件事——exe 被占用时卸载/覆盖会失败。两份旧说明里已加更正段落，原文保留。）

## 改法

Tauri 的**安装钩子救不了这件事**：钩子的四个插入点全在 Section 里，而那个维护页在**离开时**就执行了旧卸载器，**早于任何 Section**。所以这一版改成**自带一份 NSIS 模板**（从 Tauri CLI 二进制里逐字节取出、带 sha256 出处与维护说明），只改两处：

- NSIS 路径：给旧卸载器加 **`/S`**；
- WiX 路径：加 **`/qn`**（msiexec 的静默开关，`/S` 是 NSIS 专有、msiexec 会拒）。

并用"与上一版生成的脚本逐行比对"证明**上游内容零漂移**（基线独有行 = 0，新增的 32 行全是注释与那两行）。

## 静默卸载会不会删掉你的数据（发出来之前先测过）

**不会。** 静默模式下卸载器的确认页**不执行**，于是"是否删除应用数据"那个复选框状态保持为空 ⇒ `%LOCALAPPDATA%\com.dsh.wallpaper`（**设置、会话记录、已下载的安装包**）不会被删；而应用自己的数据（`catalog.db`、会话文件、素材库、导出）在安装目录里，卸载器只删它登记的文件 ⇒ **原地保留**，新版装回同一目录。

## 失败时的出路（不静默卡住）

如果旧版 exe 当时仍被占用（静默卸载失败），安装器会弹一句 **"Unable to uninstall!"** 并**退回维护页**，你可以改选「Do not uninstall」继续安装。这是设计好的出路，不是崩溃。

## 怎么验

**必须跨版本**：正在安装的版本比已装版本高，才会走这条被改的路（同版本安装走的是"重装"分支）。

从 **0.4.5 更新到 0.4.6**，预期：

1. 点「点击安装」→ **应用自己关掉**；
2. **只出现一个向导**——**不再有第二个卸载器窗口**；点完维护页的 Next 后向导会短暂消失几秒（那是静默卸载在跑），属预期；
3. 装完**自动起新版**；
4. 顺手确认：设置、会话记录、素材库、快捷方式都在。
