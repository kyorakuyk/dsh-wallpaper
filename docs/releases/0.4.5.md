# DSH Wallpaper 0.4.5（完整版 · Windows 11）

两件事：**修好设置页里一处塌陷的排版**，以及**这是第一个能验证"一步更新"的升级**。

## 修了什么

**设置页某一行被挤成"一词一行"**

「随壁纸启动 DSH」下面那条警告渲染成了：标题与说明**一词一行**、旁边一条长句**横向冲出卡片**被裁断。

原因是**一句话被当成了"控件"**：`Field` 组件的 `children` 落在右侧的"控件列"，而那一列的 CSS 是"按内容定宽、不收缩、不换行"。于是那句长文案排成一行冲出去，而同一行里**唯一能收缩的文案列**被压到只剩一个词宽。

改法：给 `Field` 增加一个落在**文案列**的 `note` 槽位；没有控件时不再画空的控件列；两列都允许收缩（并留了注释说明为什么）。同时**把文案改短**——三种变体原本各自重复了同一句半句（英文 183 → 73 字符，中文 54 → 27）。

**顺手修了一处指错页面**：那四处警告都让人去「**常规**」页开壁纸自启，而那个开关在「**系统**」页。全部改正，并加了测试钉住"文案里说的页必须真的渲染出那个开关"。

**测试**：新增 7 条，其中一条渲染**全部五个设置页**、逐行断言"控件列里不许出现裸文本"（正是这次的形态）；验证过它有牙齿——把源码还原后 4 条变红。

## 这一版是"一步更新"的第一次真正验证

顺序是有意的：

- **0.4.4** 是那个"**点安装时应用先自己退出、再由守候者启动安装器**"的版本；
- 所以**从 0.4.4 更新到 0.4.5**，才是那条改动的第一次生效：预期是**应用自己关掉 → 只出现一个安装向导**（不再先弹卸载器）→ 装完自动起新版。

如果起点是更早的版本（0.4.2 / 0.4.3），那条改动还不在运行中的那份里，仍会看到卸载器窗口——**那是旧行为，不是这一版的问题**。

## 更正（0.4.6 施工时发现，原文不改、在此说明）

本文把"可见的卸载器窗口"归因为"应用仍在运行、安装器替换不了 exe"。**那个归因是错的**。0.4.6 施工时读安装脚本并做了对照实测，真正的根因是：**Tauri 的 NSIS 模板调用旧版卸载器时从来不传 `/S`**（测法：给一个探针卸载器分别传 `_?=<目录>` 与 `/S _?=<目录>`，前者在卸载器内 `${Silent}=0` ⇒ 带界面，后者为 1）。

所以："应用先自己退出"（0.4.4）解决的是**另一件事**（exe 被占用时卸载/覆盖会失败），它仍然必要；而"两步"这个现象，要由 0.4.6 的自定义模板给卸载器加 `/S` 才消失。
