# DSH Wallpaper 0.4.3（完整版 · Windows 11）

这一版**几乎没有新功能**——它做的是把"更新检测"变得**可诊断**，以及补上两处本该有的测试。

## 为什么要发这一版

0.4.2 上线后，我在真机上遇到一个尴尬局面：**"检查从未被触发"与"跑了但被跳过"在证据上完全一样**。原因是两条"跳过"分支（读不到本机版本 / 6 小时节流）**只写日志、不写状态文件**，而日志会被轮换——我因此得出过一个**错误结论**。

## 改了什么

**跳过也留下持久痕迹**

- 状态文件新增 `lastSkipReason`（`throttled` / `versionUnavailable`），跳过时一并落盘；
- **`checkedAtMs` 的语义没有变**：它代表"真正查过的时刻"，节流靠它。"读不到版本"那条分支**不写它**——否则那台机器会永远不再检查（两条都有测试钉住）；
- 顺手修掉一处**撒谎**：跳过时的报告原本无条件声称"状态已落盘"，现在如实反映；
- 旧状态文件缺少这个键时按默认值读取（向后兼容，有测试）。

**两处补上的测试**

- **触发行为测试**：这条是真正缺的那条——以前对"进入里桌面会触发检查"的覆盖都是**读源码**，现在会真的挂载组件、在真渲染器里跑 effect，断言"表桌面不调、进入里桌面调一次、反复进出不再调"。**"点了没反应"正是这类缺陷的典型症状**；
- **真实网络测试**：默认 ignore，手动跑；它真的向 GitHub 发一次请求并解析，验证"请求 + 解析"这段胶水（单测里被注入的取数入口替掉了）。本机实测返回 `v0.4.2` 与 62,268,609 字节的资产。

**一处门禁稳定性修复**

一条新测试在构建机上偶发失败（只让出一个宏任务，机器忙于编译 cargo 时不够）。已放宽为最多 100 ms 的让出循环，并**在提交里写明这只是放宽窗口、不是消除依赖**——正确写法是"等待期望状态"，留给下次改动这个文件时做。

## 功能本身（与 0.4.2 相同）

进里桌面 → 有新版本时立绘上冒气泡（「下载」「忽略」）→ 下载显示进度 → 完成后点「点击安装」交给 Windows 安装向导；设置中心 → **系统** 里有同一张卡片（当前版本、上次结果、手动检查）。规矩不变：**点一下气泡不会升级**、**没点过不等于忽略**、**不点下载就不下载**。

## 已知边界

- **真机点击链路仍未验证**：气泡 → 下载 → 安装向导这三步需要人点，自动化只能覆盖到它的两侧（触发与网络）。这一版把诊断补上了，正是为了让那一次点击**无论成功失败都留下确定答案**；
- 其余边界同 0.4.2（没有取消下载、重启不恢复"已下载"、中断会留下 `.part`、原生自由文本仍是中文）。
