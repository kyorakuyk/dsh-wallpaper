# 设置中心窗口：圆角与那圈系统边框

记录时间：2026-09-26。被测安装版：0.2.0.95 → **0.2.0.98**（结论以 0.2.0.98 为准）。
复现脚本：`input-probe/settings-corner-check.ps1`（等窗口出现后自动读 DWM 属性、截窗口、
放大四角、并做"窗内 vs 窗外"的像素对照）。

## 1. 用户看到的问题

设置中心四角是**尖的**，用户要求"用 Windows 11 默认的圆角就行"。

## 2. 真实成因（两层叠加，都不是"忘了设圆角"）

1. **原生侧主动把圆角关掉了**：`apply_settings_window_frame_policy` 里写着
   `DWMWA_WINDOW_CORNER_PREFERENCE = DWMWCP_DONOTROUND`，注释说明理由是"CSS 自绘圆角轮廓，
   再叠一层 DWM 圆角会在曲线外产生亮边"。
2. **CSS 侧的圆角被自己盖住**：`.settings-window` 用不透明底色 `#0d1625` 铺满整个方窗，
   而内层 `.settings-app` 的 22px 圆角在它**下面**——所以即使圆角存在也看不见。
3. 于是**没有任何一层在画圆角**。而用户实际看到的"尖角"，还有一层更明显的东西：
   **一圈白色的系统边框**（见下一节）。

## 3. 那圈白色是什么（实测判定，不是猜）

| 量测 | 结果 |
| --- | --- |
| 窗口矩形 | 1402×1033 |
| 左/右/下 | 各 **11 物理像素**亮色（亮度 206–219） |
| 顶 | **2 像素**，且是**暗**的（亮度 16–21） |
| 程序自报 | `client-origin-offset=(11,2), client=1380x1020` |

"三边亮、顶部暗且只有 2px"正是**可调边框**的形状：顶部是标题栏（我们设过 `DWMWA_CAPTION_COLOR`
所以是暗的），左/右/下是可调边框——而**本机 Windows 是浅色主题**，DWM 用系统浅色画它。
换句话说：**客户区永远比窗口矩形小 (11,2)，CSS 只能画到客户区为止**，那圈颜色由系统主题决定。
改 caption/border 颜色只是跟它较劲，换主题就会再次不一致。

## 4. 最终修法（0.2.0.98）

- **`WM_NCCALCSIZE` 返回 0**（子类里）：非客户区归零，**客户区 = 整个窗口矩形**，
  深色面板可以一直画到边缘，那圈框从结构上不存在，与主题无关。
- **自绘缩放命中带**（`WM_NCHITTEST`，边缘 8 逻辑像素报 `HTLEFT/HTTOP/…`）：
  框架没了 Windows 就不再提供"拖边改大小"，必须补回来，否则窗口不能缩放。
  只在贴边一圈生效，其余交回默认结果，**不会吞 WebView 的点击**。
- **`DWMWCP_DEFAULT`**：圆角交回 Windows 11（用户要求的"系统默认"）。
- **`DwmExtendFrameIntoClientArea(-1)`**：无框架窗口靠它保留系统圆角与阴影。
- **`DWMWA_USE_IMMERSIVE_DARK_MODE = 1`** + `DWMWA_CAPTION_COLOR`：框架按深色绘制，与面板同族。
- **CSS**：`.settings-window` 底色改透明（不再盖住圆角），`.settings-app` 半径 22px → **8px**
  （= Windows 11 系统默认窗口圆角）。两道弧半径必须一致：CSS 半径更大就会在两道弧之间露出缺口。

## 5. 四个只有实测才会暴露的坑（勿回退）

1. **`.decorations(false)` 对"从未显示过"的窗口不生效**（悬浮球那一轮已踩过一次）：
   实测样式仍是 `WS_OVERLAPPEDWINDOW - WS_THICKFRAME + WS_CLIPSIBLINGS`，
   `WS_CAPTION|WS_SYSMENU` 都在、`WS_POPUP` 从未设置。
2. **Windows 会缓存客户区矩形**，只在 `WM_NCCALCSIZE` 时重算。tao 在创建窗口时已算过一遍
   （那时我们的子类还不存在），所以子类里那段"非客户区归零"**永远等不到消息**：
   0.2.0.97 的日志里 `client-origin-offset` 仍卡在 `(11,2)`。
   修法是**先装子类、再 `SWP_FRAMECHANGED` 强制重算一次**。
3. **框架颜色跟着系统主题走**，不是跟着我们的面板颜色。浅色主题下不改深色模式，
   那圈就是白的。
4. **`client-origin-offset` 是这项改动的自检指标**：必须从 `(11,2)` 变成 **`(0,0)`**，
   否则说明非客户区还在、CSS 仍然画不到边。

## 6. 实测验收（0.2.0.98）

| 检查 | 结果 |
| --- | --- |
| 客户区 | `client-origin-offset=(0,0), client=1402x1033` = 整个窗口矩形 ✓ |
| DWM 圆角偏好 | `0 (rounded, system default)` ✓ |
| 窗口样式 | `0x14CF0000`，`thick_frame=true caption=true`（样式保留，靠 NCCALCSIZE 归零）✓ |
| 左上/右上放大图 | 圆角弧线干净，**弯角外没有任何系统色亮条** ✓ |
| 窗内像素 | 沿对角线从 d8 起即面板色 `#142234`，不再出现白色像素 ✓ |

## 7. 未验证

- 浅色/深色主题各自的表现只在本机（浅色主题）量过。
- 缩放手感（自绘命中带）只做了代码审查：**需要用户实际拖一下边框确认**。
- 多屏、非 150% 缩放、窗口最大化（本窗口不可最大化）未测。

## 8. 去掉框架的两个连带影响（0.2.0.99 / 0.2.0.100）

**8.1 缩放改由渲染层发起（0.2.0.99）**

去掉非客户区后，Windows 不再提供"拖边改大小"的命中区；而**原生命中带根本不会被执行**：
WebView2 渲染窗口属于另一个进程、铺满整个客户区，鼠标命中测试归它，父窗口的
`WM_NCHITTEST` 从不被问到——与桌面输入模型里那条实测结论同因。
因此 `SettingsWindow.tsx` 加了 8 条不可见边条（贴边 6 逻辑像素、四角 12），按下即调
`startResizeDragging`；capability 里补 `core:window:allow-start-resize-dragging`。
原生命中带 `resize_edge` 保留作兜底，但注释写明它在 WebView 覆盖区内不会被执行。

**8.2 透明窗口会露出 WebView 的默认白底（0.2.0.100）**

用户实测：快速拖动窗口时出现**白色虚影**。根因是 0.2.0.95 把 CSS 根节点改为透明后，
WebView2 自己的默认底色（白）成了"还没画上内容的地方"的底色，拖动/重绘跟不上时那片
区域就闪白。修法是给设置窗口设**背衬底色**：

```rust
.background_color(tauri::window::Color(0x0d, 0x16, 0x25, 0xff))
```

来不及重绘时露出来的是深色，与面板几乎无差别。**注意**：不要顺手把窗口改成不透明来
"根治"闪影——那样 `.settings-app` 的 `backdrop-filter` 就没有可采样的背景，亚克力质感会
一起消失，属于另一个层次的视觉改动。

**8.3 这条改动只作用于完整版**

去掉非客户区那一步用 `#[cfg(not(feature = "lite"))]` 限定：Lite 的设置界面是另一条工作流的
文件，没有配套的缩放边条，去掉框架会让它既没边框也不能缩放。
