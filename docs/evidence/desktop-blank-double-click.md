# 桌面空白处双击：判据、围栏与探针证据

记录时间：2026-09-30。这份文档记的是「双击桌面空白处在表/里桌面之间切换」这个功能的**判定依据**、
**配对围栏**，以及支撑它们的**真机探针结果**。功能本身在 `windows_integration.rs`，可复用的探针在
`scripts/` 下。

---

## 一、一句话结论

判据换成 **MSAA（旧接口）的三态**：从 Explorer 固定的图标列表出发，用 `accHitTest` 问"光标这一点
落在图标上、还是桌面上"；只有"**确认空白**"才允许切换。配对用**两态状态机**保证点击严格两两匹配，
快速连点不会重叠配对。

## 二、为什么不能用 UI Automation

实测（本机，表桌面，图标层可见）：

| 读法 | 结果 |
| --- | --- |
| 列表自报数量 `LVM_GETITEMCOUNT` | 17 |
| UIA `Children` 且 `ListItem` | 0 |
| UIA `Descendants` 且 `ListItem` | 0 |
| UIA `Children` 全部（不筛类型） | 0 |
| UIA `ItemContainerPattern` | 不支持该模式 |

**这台机器的桌面图标在 UI Automation 树里是空的。** 此前"命中查询看不到图标"的真正原因就在这里，
不是覆盖层遮挡。于是任何基于 UIA 的"没找到图标 ⇒ 这里是空白"的判断都必然错，而且错的方向恰好有害：
把图标当空白 ⇒ 双击快捷方式会顺带翻掉桌面层。

## 三、MSAA 一次就通

同一个列表句柄，换旧接口：

```
AccessibleObjectFromWindow(OBJID_CLIENT) -> hr=0x00000000
accChildCount = 18
  子项 1  'Comfy Desktop'   (0,5)    114x127
  子项 2  'WorkBuddy'       (0,159)  114x103
  子项 3  'ZCode'           (0,313)  114x103
```

在该对象上做 `accHitTest(x, y)` 的实测（七个点，零歧义）：

| 点 | 性质 | accHitTest 返回 |
| --- | --- | --- |
| (57,68) | 图标 1 | 子项编号 1 |
| (57,210) | 图标 2 | 子项编号 2 |
| (57,364) | 图标 3 | 子项编号 3 |
| (200,1000) (1000,1000) (900,400) (1500,950) | 桌面空白 | 0 |

两条前提也在同一批测量里确认了：**图标层当时可见**（`SHELLDLL_DefView` 与 `SysListView32` 都是
visible），且这些点确实属于桌面（窗口父链走到桌面类名）。窗口盖住桌面时点不属于桌面，判"不是桌面"
是对的，不是缺陷。

## 四、三态判据与它为什么必须是三态

```
Icon     落在图标上（子项编号大于 0）  -> 不切换
Blank    确认空白（子项编号为 0）      -> 允许切换
Unknown  取不到对象 / 子项数为 0 / 调用失败 / 返回值不是整数 -> 不切换
```

三态是刻意的：**判错的代价不对称** —— 把图标当空白，会让"打开快捷方式"顺带翻掉桌面层；把空白当
图标，只是偶尔不切换（悬浮球仍在）。所以一切读不出来的情形都归入 `Unknown`，绝不退化成空白。

## 五、配对围栏（两态状态机）

```
Idle  ──合格且干净的一下────────────────▶ Armed(时刻, 位置, 模式)
Armed ──第二下合格、同模式、≤500ms、≤64px──▶ 切换 + 冷却 350ms ──▶ Idle
Armed ──以上任一条件不满足──────────────▶ 作废 ──▶ Idle     ← 不回退成"新的第一下"
任意  ──不合格 / 带组合键 / 是拖动 / 冷却期内──▶ Idle
```

**为什么要围栏**：早先的写法在"第二下没配上"时把它留作新的第一下，于是快速连点会形成 1-2、2-3、
3-4 的重叠配对，一次连点拨动好几次。现在第二下不成立就作废，一次连点最多拨动一次，中间还要过冷却。

判定按**两拍**理解（用户总结）：第一下判定（三态，在按下那一刻取，因为点击的目标由按下决定），
第二下执行。配对在**松开**时成形，所以拖动天然被排除。

现用阈值（都在 `windows_integration.rs` 顶部常量里）：

| 项 | 值 | 说明 |
| --- | --- | --- |
| `PAIR_WINDOW` | 500ms | 两次点击的最大间隔，与本机系统双击间隔一致 |
| `PAIR_REACH_PX` | 64 | 两次点击的最大位置差（物理像素） |
| `CLICK_MAX_MS` | 400 | 一次按下最长时长，超过算拖动 |
| `CLICK_MAX_MOVE_PX` | 12 | 一次按压期间允许的位移 |
| `PAIR_COOLDOWN` | 350ms | 切换之后的冷却，期间不配对也不上膛 |

模式条件：两次点击必须发生在同一个桌面模式（表/里），跨模式不配对。

## 六、走过的弯路（写下来免得重走）

1. 第一代：按窗口**类名**判断"这一下是否启动了别的东西" —— 点空白时前台会落到 Explorer 自己的
   窗口（`SHELLDLL_DefView` 之类），被判成"别人"，功能静默失效；
2. 第二代：按**进程号**判断 —— 用资源管理器打开文件夹/文件时动作也由 explorer 完成，进程号不变，
   于是那类点击被放行，图标位又翻桌面；
3. 第三代：按**窗口句柄** + 桌面表面类 —— 漏掉"双击壁纸自己的桌面图标"（应用已在运行，进程号不变、
   只换窗口）；
4. 第四代：加 UIA"桌面归属"信号与 `#32769` 类名 —— 过宽（UIA 树的根就是桌面，爬够远谁都能碰到它，
   任务栏按钮因此被误放行），于是又收紧成"三层以内"；
5. 同时期还试过"图标矩形 + 三重过滤"（非本进程、不离屏、尺寸像图标），当时失败的原因是**从光标下的
   Pane 向下枚举**，把并非 Explorer 图标的列表项也算了进去；
6. 真正的转折是**先做只读探针**：确认 UIA 读不到、MSAA 读得到、`accHitTest` 能区分图标与空白，然后
   才动代码。此前四代都是在没有这条地基的情况下调参，方向一错就要一轮装机。

## 七、怎么复现这套测量

`scripts/` 下两个只读探针（不注入 Explorer、不发鼠标消息、不改状态）：

* `probe-desktop-icon-list.ps1`：报告图标层是否可见、图标列表句柄、自报数量、MSAA 读到的子项数与
  前几个矩形；里桌面状态下会明确说明"读不到是正常的"。
* `probe-msaa-hit-test.ps1`：取前几个图标矩形中心与若干候选空白点，分别打印 `accHitTest` 结果与窗口
  父链是否到桌面；用来验证三态判据在当前机器/当前状态是否成立。

用法：桌面露出来时运行即可（`Win+D` 或把窗口最小化）。若某台机器上 MSAA 也读不到，按同样的取舍处理：
判"无法确认"、不切换，保留悬浮球入口。

## 八、已知边界与未做的事

* 判据只在**桌面真的露出**时成立；桌面被窗口盖住时点不属于桌面，不切换（这是设计，不是缺陷）；
* **里桌面**（图标层被隐藏）目前仍走同一套判定：三态会判"无法确认" ⇒ 不切换。"让 WebView 的空白
  区域自己处理里桌面的双击"这条尚未实现；
* 可配置**全局热键**那条入口尚未实现（说明里需写明锁屏、安全桌面与热键冲突时可能失效，不做"任何
  时候都有效"的承诺）；
* **立绘（角色画）已按"我们自己的内容"处理**（2026-09-30 实现）：两处 `<img>`（`scenes/IdleScene.tsx`、
  `lite/LiteIdleScene.tsx`）标上 `data-interaction-region="persona"`。这一条同时解决两件事——热区的点击
  转发给我们自己的窗口，所以输入岛的展开状态不再被重置；原生判定里的 `cursor_hits_interaction_region`
  成立，所以那里不会被当成桌面空白。**原生侧一行未改**，三态判据、配对状态机与阈值都保持原样。
  代价要记住：立绘区域内的点击不再穿透，因此**视觉上压在立绘之上、位于桌面图标层的图标在那块区域内点不到**。
  这是"把立绘当作我们的内容"的必然结果，若将来觉得碍事，可改为单独一份"不算空白但不拦截点击"的声明
  （那需要前端多加一个字段、原生多加一条判定）。
* 探针只在**本机**验证过（Windows 11，图标层可见/隐藏两态各测一次）。
