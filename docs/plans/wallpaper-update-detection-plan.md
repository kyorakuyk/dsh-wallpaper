# 壁纸更新检测与立绘更新气泡（计划书）

状态：**待施工**（本文只是计划，未动代码）。写于 2026-09-29。

用户已确认的四条规矩（施工时按原样执行，不要重新设计）：

1. 更新源就是 GitHub Releases；
2. 检测到之后按"下载 → 交给 App Installer 安装"做，下载失败回落"打开 release 页面"；
3. 气泡上**必须有「下载」与「忽略」两个按钮**：不允许"点一下气泡就升级"，也不允许"没点过就算忽略"；
   只有按下「忽略」才算忽略；
4. 时机：现有序列是 **帧动画 → 切到表桌面 → 立绘冒「早上好…」 → 用户进里桌面**。
   更新气泡**在进入里桌面之后**出现（表桌面阶段不出现）。
   Lite 版本次不做（后续更新意义不大），但可以给一个纯提示。

---

## 一、范围

做：

- 设置中心里一行「更新」：显示当前版本、上次检查时间与结果，并提供手动「检查更新」；
- 立绘上的更新气泡：`新版本 → 下载 → 进度 → 可安装`，带「下载」「忽略」两个按钮；
- 一个原生侧的更新检查与下载实现（含进度事件），以及版本比较与状态持久化。

不做：

- 静默安装 / 自动升级（MSIX 无法自我替换，且必须由用户点安装）；
- Lite 版的完整功能（只给提示，理由与边界见第七节）；
- 自建更新源、增量下载、差分包。

## 二、现状与前提（已核实）

| 事实 | 依据 |
| --- | --- |
| 壁纸是 MSIX 包，**不能自我替换** | 包由 Windows 部署；升级必须走 App Installer 或 Store |
| 当前版本可读 | 打包态用 `Package.Current.Id.Version`（四段，如 `0.2.0.202`）；非打包（调试）态没有包身份，此时**跳过检查**而不是猜版本 |
| 仓库已有 release 流程 | `.github/workflows/package.yml` 的 `release` 任务只在 `v*` 标签上跑，`gh release create` 上传构建产物 |
| **标签还不是版本号** | 现存标签是 `checkpoint-2026-09-28` 这类，无法比较大小 ⇒ **先要约定**（见第三节） |
| 网络能力 | 完整版已有 `reqwest`；它是 `full` 专属依赖 ⇒ 本功能天然属于完整版 |
| GitHub API | `GET https://api.github.com/repos/<owner>/<repo>/releases/latest`，匿名可用（每小时 60 次，够用），**必须带 User-Agent**，否则 403 |

## 三、先决条件：标签与产物约定

检查"有没有新版本"要求标签可比较。约定如下（需要用户点头，之后固定写进发布流程）：

- 标签格式：`v<四段版本>`，与 MSIX 版本一一对应，例如 `v0.2.0.203`；
- release 至少带一个资产：`dsh-wallpaper-lockscreen-test.msix`（沿用现在 CI 的产物名）；证书 `.cer` 不必随 release 走——更新场景下证书早就被信任了；
- 版本比较：解析标签去掉前缀 `v`，按四段数字比较；只接受 `^v\d+(\.\d+){0,3}$`，解析不出的 release 一律按"没有新版本"处理（宁可漏报，不可误报）。

## 四、交互与状态机

气泡只有下面这些状态，任何状态都**不会**因为"用户没动它"而自行变化：

```
idle ──检测到新版本──▶ available ──按「下载」──▶ downloading ──成功──▶ ready ──点「安装」──▶ handing-off
                         │                        │
                     按「忽略」                 下载失败
                         ▼                        ▼
                     dismissed(记版本)          failed ──可重试──▶ downloading
```

- `available`：气泡文案「有新版本 0.2.0.203」，两个按钮：**下载**、**忽略**；
- `downloading`：同一枚气泡变成进度条（「正在下载 42%」），进度来自原生侧的流式下载事件（每 ~200 毫秒一发）；
- `ready`：文案变「点击安装」，点击后用 `ShellExecuteW("open", <msix 路径>)` 交给 App Installer；
- `failed`：显示可读原因（网络/校验/磁盘）＋「重试」；
- `dismissed`：**只有按「忽略」才会进入**，记录该版本号；更晚的版本仍会提示；
- 没点任何按钮：本次会话保留气泡，**下次启动仍会出现**（不写任何"已忽略"记录）。

其他约束：

- 气泡挂在立绘槽位（`.portrait-slot`，那里已有 `.bubble` 样式可复用）；点击气泡必须 `stopPropagation`，否则会顺带打开对话；
- 出现时机：**用户进入里桌面之后**（工作区切到 inner 且已过唤醒动画）；锁屏、表桌面、对话展开时都不出现；
- 同一时刻最多一枚气泡（与「早上好…」那枚不冲突：那枚在表桌面阶段，本枚在里桌面阶段）。

设置中心一行「更新」：

- 显示：当前版本、上次检查时间、上次结果（已是最新 / 有新版本 x / 检查失败的原因）；
- 一个「检查更新」按钮（手动检查不受频率限制）；
- 有新版本时，此行也提供「下载」与「忽略」（与气泡同一状态机，同一份状态）。

## 五、数据与持久化

- 状态文件：`%LOCALAPPDATA%\com.dsh.wallpaper\updates\state.json`，字段至少包含
  `latestVersion`、`checkedAtMs`、`dismissedVersion`、`downloadedPath`、`downloadedSha256`；
- 放原生侧而不是 WebView 的 localStorage：这份状态要在壁纸重启后仍然有效，而 localStorage 属于那个 WebView 实例；
- 自动检查频率：启动后首次进入里桌面时检查一次，之后**每 6 小时**最多一次（手动检查不受限）；
- 检查失败**不弹气泡**，只在设置里留一行结果（不打扰是设计目标）。

## 六、下载与安装

- 资产选择：release 资产里取 `.msix`（本功能只属于完整版；将来若给 Lite 做，需要按版本选对应资产）；
- 保存位置：`%LOCALAPPDATA%\com.dsh.wallpaper\updates\<版本>\<资产名>`；
- 校验：下载完成后核对 GitHub API 给出的资产大小（有 `digest` 时一并核对 sha256）；不符即删除并报 `failed`；
- 安装：`ShellExecuteW("open", <msix 路径>)` ⇒ 走 App Installer 的界面，由用户点安装。
  **已知失败模式**：机器上没信任签发证书时，App Installer 会拒绝——这正是"必须由用户点、且看得见原因"的另一个理由；
- 回落：资产不存在或下载失败 ⇒ 提供「打开 release 页面」（复用现有的浏览器打开路径）。

## 七、Lite 版（本次只做提示）

按用户决定，Lite 不做完整功能。可接受的最小形态：设置里一行说明「Lite 版暂不支持应用内更新检查；请从发布页获取新版本」并给一个打开发布页的按钮。理由要写清：Lite 是有对外发布包的那个版本，但更新检查的下载/安装链路与主程序共用同一套证书与包管理器，单独维护会引入第二套不一致。

## 八、验收条件

1. 表桌面阶段（含「早上好…」气泡期间）**不出现**更新气泡；进入里桌面后才出现；
2. 气泡上有「下载」与「忽略」两个按钮；点气泡本体不做任何升级动作；
3. 按「忽略」后：该版本不再提示；重启壁纸也不提示；出现更新的版本仍会提示；
4. **不点任何按钮**：关掉壁纸再打开，气泡仍然出现（不写入任何忽略记录）；
5. 按「下载」：气泡变成进度条，百分比单调递增且最终 100%；文件落盘且大小与 API 一致；
6. 下载完成：文案变「点击安装」，点了之后 App Installer 起来（或给出可读的拒绝原因）；
7. 断网或资产缺失：设置里能看到失败原因，气泡不反复冒；恢复网络后手动检查能成功；
8. 启动时不会每次都打网络：6 小时内只检查一次（可用日志核对）；
9. 非打包（`tauri dev`）运行时不报错、不误判版本，只是不检查；
10. 设置里的当前版本与 `Get-AppxPackage com.dsh.wallpaper` 的版本一致。

1. 约定落地：标签格式 `v0.2.0.<N>`、release 带 MSIX 资产（改 CI 与发布脚本，一处文档一处脚本）；
2. 原生：版本读取、GitHub 检查、状态文件、版本比较（含单测；网络层可注入以便测试）；

4. 设置中心那一行（当前版本 / 上次检查 / 检查按钮 / 下载 / 忽略）；
5. 立绘气泡组件与"进入里桌面"的触发时机（含它与「早上好…」气泡不冲突的测试）；
6. Lite 的提示行。

## 十、细节默认值（若用户无异议即按此实现）

- 自动检查间隔：6 小时；
- 下载中**不提供取消**（只显示进度；要取消就关掉壁纸，已下载的部分留在缓存目录，下次重下）；
- 气泡在立绘右上角，宽度自适应，长版本号不换行；
- 「忽略」记录的是"具体版本"，不是"忽略全部"；
- 失败提示保留最近一次原因，供设置页显示。
